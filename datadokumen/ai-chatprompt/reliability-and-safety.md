# Reliability and safety

## Reliability and safety

Reliable answers require clear sources, controlled generation, and regular evaluation.

### When the assistant must not answer

The assistant should decline or qualify an answer when:

* No documentation supports the claim.
* The question needs private account data or human approval.
* Sources disagree or may be outdated.

### Fallback response

```
I cannot confirm that from the available documentation.
Please share more context or contact the support team.
```

### Quality checks

Review these questions after every documentation release:

1. Does each answer cite relevant sources?
2. Does the answer match the documented default and limitations?
3. Does it state uncertainty rather than guessing?

### Improve weak answers

Add missing product details to documentation. Use clear headings, exact values, and task-based examples. Then test the same user question again.
